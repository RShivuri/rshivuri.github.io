Multi-tenant WhatsApp CPaaS and e-commerce backend

C# · .NET 8 · Minimal APIs · Clean Architecture · Meta Cloud API

The problem
Small merchants sell on WhatsApp by hand: a catalogue pasted into chats, orders copied into spreadsheets, payment confirmations lost in threads. Serving many of them from one platform means every tenant needs its own number, catalogue, keys and order book, while Meta exposes a single webhook that must answer in seconds and may redeliver.
The solution
One .NET 8 service resolves the tenant from the inbound phone_number_id, verifies the X-Hub-Signature-256 header, acknowledges the webhook immediately and hands the event to a background processor. Message ids are stored for idempotency, so a redelivery never creates a second order. Catalogue, cart, order and payment link are aggregates in the domain layer. Outbound messages go through an outbox so a failed send is retried without duplicating the customer's conversation.
Architecture
Domain, Application, Infrastructure and Api projects. Minimal API endpoints grouped per bounded context with typed results and an endpoint filter for tenant resolution. EF Core with a tenant-scoped DbContext. Hosted services for the inbound queue and the outbox. Public media from a separate assets repository.

Synthetic South African identity and banking data API

C# · .NET 8 · Minimal APIs · Luhn · AVS · civil registry

The problem
CRM and payments systems in South Africa validate what they ingest: a 13-digit ID number must pass the Luhn check and encode a real birth date, gender range and citizenship digit; a bank account must survive Account Verification Service (AVS) rules on branch code and account type. Teams either tested with production data they should not have had, or with fake data the validators rejected before the real logic ran.
The solution
An API that generates records which pass every validator and carry no real person. Identity profiles are built from a birth date, a sequence in the correct gender range, the citizenship digit and a computed Luhn check digit. Banking details come per bank with valid universal branch codes and the AVS outcome a tester wants (match, no match, account closed). Civil registry events (birth, marriage, death) are linked records, so a death can invalidate the identity it belongs to. Every request takes a seed, so a fixture is regenerated byte for byte in another environment.
Architecture
Endpoints under /v1/identities, /v1/bank-accounts and /v1/civil-registry, each backed by a pure generator in the domain layer with no I/O, which is what makes the output deterministic and unit-testable. Bulk endpoints stream NDJSON or CSV so a Dataverse seeder loads thousands of rows in one call.

Enterprise CRM automation and white-label delivery at Paycorp Group

Dynamics 365 CE · Dataverse · Power Automate · Azure DevOps · C# SDK harness

The problem
An ATM and payments CRM where sales-to-live onboarding, change control, settlement and banking integration all ran through hand-built flows and hand deployments. Flow families drifted between dev, QA and production. Production automation ran on personal accounts. Nobody could say, before a release, whether a Change of Ownership or a Rebrand would still reach the Settlement queue.
The solution
An Azure DevOps release pipeline that deploys a versioned manifest to QA and then production, with a pre-flight check, a service-principal identity and two-person approval at each stage. A C# .NET test harness on the Dataverse SDK that drives records through business process flows and approval queues, proving five change-control processes end to end before every release. Brand-specific white-label email templates and notifications for portal tickets, customer acknowledgements and team alerts. Production automation moved onto service accounts, and every flow family aligned to one definition across environments.
How the work is done
Forensic analysis of the live flow definition, a patch in dev, a component diff against the target, and a read-back after every deploy. Each change is a change record with evidence. Solution architecture packs (arc42, C4, ERD, event-pipeline maps) and AI-assisted runbooks let the rest of the team investigate and change Dataverse safely.
